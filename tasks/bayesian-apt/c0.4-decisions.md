# C0.4 Decisions — CMP Index Construction

## Context

C0.4 landed in `kask/mcp-servers/hkask-mcp-prediction-markets/src/cmp_index_builder.rs`.
The builder reads the per-family catalog JSONL files, adapts each record to the
eligibility pipeline, and calls the existing `construct_cmp_index_set` from
`cmp_portfolio.rs` (C0.3). Provenance (family, venue) is wrapped onto each
`CmpIndex` via `ProvenancedCmpIndex`.

## CP-CMP checkpoint findings (rates family) — post-ONT-6

### ONT-6 fix (2026-08-07)

The C0.4 probe found the `InterestRates` substring signature didn't cover
Polymarket phrasings. ONT-6 rewired the catalog builder to use the FIBO-anchored
`semantic_mapping::classify_base_object_from_catalog` instead of
`base_event::classify_base_event_text`. The fix:

1. **Extended `resolve_gamma_event`** to cover: "upper bound", "federal funds
   rate" (full phrase), "rates hit/stay above", and non-Fed central banks
   (ECB, BoE, BoC) — all the same economic object under FIBO
   `PolicyInterestRate`.
2. **Added `classify_base_object_from_catalog`** — a public function that
   bridges the on-disk catalog record fields to the semantic mapping. For
   Kalshi: extracts the series prefix from `event_ticker` and passes it to
   `resolve_kalshi_series`. For Gamma: passes the `question` as the title to
   `resolve_gamma_event`.
3. **Updated `cmp_index_builder.rs`** to use `classify_base_object_from_catalog`
   instead of `classify_base_event_text`.

### Remaining diagnosis (post-ONT-6)

The classifier is no longer the bottleneck. The remaining CP-CMP gaps are
**genuine venue characteristics**:

1. **Kalshi 1m/2m/3m**: each bucket has contracts but only at a single
   maturity (1m: all at 24d; 2m: all at 54d; 3m: all at 82d). No bracket pair
   spans the target. The FOMC-meeting contracts (KXFED-_) cluster at 40d,
   82d, 124d, 173d — the 3m window [67.5, 112.5] contains only the 82d
   contracts. The Treasury-yield contracts (KXUST_) fill the 1m/2m windows
   but at a single maturity each.

2. **Polymarket all tenors**: all contracts at 124d (Dec 9) or 146d (Dec 31).
   No contract at or above 180d → no 6m bracket. No contract below 124d →
   no 1m/2m/3m bracket. The Polymarket rates market is a year-end market,
   not a continuous ladder.

These are structural properties of the rates market, not bugs. The CP-CMP
checkpoint correctly diagnoses them.

## Resolution of the four open questions (cmp-foundation §6)

### 1. Magnitude bands: fixed per family vs continuous with tolerance?

**Resolution: continuous with tolerance.** The `materiality_level` function
computes a continuous level from volatility × tenor scaling, and
`classify_orientation` compares the contract's strike-to-reference distance
against that continuous level. There are no fixed bands (e.g. "25bp / 50bp /
100bp"). The tolerance is the materiality level itself — a contract is
Increase when its predicted move exceeds the level, Decline when it exceeds
in the other direction, Stable when it doesn't. This is the volatility-based
design from cmp-foundation §4, and it's what the code already does.

### 2. Orientation: independent increase/decrease index pairs vs one signed index?

**Resolution: independent pairs.** The builder constructs three independent
indices per (bucket, venue): Increase, Decline, and Stable. Each has its own
portfolio of constituents. This is the plan default and what the code already
does (`construct_cmp_index_set` iterates over all three orientations). A
signed index (one number, positive = increase, negative = decline) would lose
the Stable index and conflate the two directions — the independent-pairs
design preserves the full information.

### 3. Cross-venue: per-venue indices vs pooled with adjustment?

**Resolution: per-venue, confirmed by measuring cross-venue divergence.**
The builder produces separate `ProvenancedCmpIndexSet`s for Kalshi and
Polymarket — they are never pooled. The CP-CMP probe confirms this is right:
Kalshi rates publish 3m/6m; Polymarket rates publish nothing (classifier gap
aside, the contract structures are fundamentally different — Kalshi has
per-FOMC-meeting strike-bracketed contracts; Polymarket has year-end "how
many cuts" contracts). Pooling these would be meaningless. The law-of-one-price
failure (arXiv:2601.01706) is real and venue-specific.

### 4. Sparse ladders: withhold vs publish degraded with wide error?

**Resolution: withhold.** The builder withholds (returns `CmpError::NoBracket`
or omits the index from the published set) when no bracket spans the target.
This is the never-fabricate posture. The CP-CMP probe confirms withhold is
right: the 1m bucket on Kalshi withholds because no policy-rate contract
brackets 30d, and publishing a "degraded" index with a wide error would be a
fabricated probability — the exact disease CMP exists to cure. The withheld
buckets are surfaced explicitly in `withheld_buckets` so the operator knows
what's missing and why.

## Trailing window

The CP-CMP checkpoint is a single-day probe (`run_cmp_checkpoint`). The
≥90%-of-days criterion over a trailing window is the caller's responsibility
— run the probe daily over the window and count the published days. The
recommended trailing window is **30 days** (a calendar month, covering at
least one FOMC meeting cycle). This is a passed variable in the caller, not
embedded in the builder.

## What C0.4 does NOT fix (inherited issues)

1. **Unit mismatch in `EconomicContext` defaults**: the InterestRates default
   has `volatility: 25.0` (bp) but `reference: 5.375` (percent). The
   materiality level computation produces a number in bp, but
   `classify_orientation` compares it to `move_size` in percent. This is a
   C0.1/C0.3 materiality review task — C0.4 inherits it and works around it
   in tests by using `volatility: 0.25` (percent). The real-catalog smoke
   test uses the default context and still produces indices because the
   Kalshi rates strikes (1.0%–6.0%) are far enough from the reference
   (5.375%) that the orientation classification is correct despite the unit
   mismatch (the level is so large that almost everything is Stable, but
   the 3m/6m indices still publish with Stable orientation).

2. **Signature coverage gap**: the `InterestRates` signature doesn't cover
   Polymarket phrasings ("Fed's upper bound", "reach X%"). This triggers
   ONT-6.

3. **1m tenor gap for rates**: FOMC meetings are ~6 weeks apart, so the
   shortest policy-rate contract is ~40d. The 1m (30d) tenor is below the
   FOMC cadence. This is a genuine venue characteristic, not a bug — the
   rates family may never publish a 1m index on either venue. The plan's
   CP-CMP criterion ("≥90% of days have a non-withheld index at each tenor")
   may need to relax the 1m requirement for the rates family specifically,
   or the 1m rates index may need to use Treasury-yield contracts (a
   different economic object) as a proxy. This is a research decision for
   the next session.
