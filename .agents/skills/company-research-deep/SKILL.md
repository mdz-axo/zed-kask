# Company Research — Deep Report

## Goal and boundary

From a request naming an identifiable company alone, publish a sourced full background, overview and evidence-qualified outlook report and a short summary. Derive the symbol, as-of date, and research questions yourself. Never require the user to supply a ticker, test company, source list or thesis. If the identity is genuinely ambiguous, ask only which company they meant. A gap or failed tool changes the report's label and content; it does **not** prevent delivery. Never fabricate facts, prices, quotes, audited status or a verification verdict. This is a research report, not a trading signal.

**Default path:** collect relevant evidence → write the full report and summary → mechanical draft scan → publish both frozen drafts as incomplete → one independent verify-late-gate → upgrade labels only on a passing review. No candidate note, early gate, mandatory LISTEN, GORILLA, Wardley, Simon, EQM, essentialist, scenario or thesis-judge stage belongs on this path. Do not run those stages merely because a template exists. Do not wait for a complete investment thesis before producing a company report. A reader can see which sections could not be supported.

## Default report path

1. **Collect once.** Call `resolve_symbol` for a listed company and `begin_research_run`; use the returned run ID on relevant `web_search`/`web_extract` calls. Prefer the company's latest audited annual filing for historical financial facts, then its latest interim filing (explicitly unaudited), its own description, and one current and one prior management statement where available. Retrieve a relevant independent competitor/industry source only when the comparison matters. Fetch the actual document before citing it; search snippets and model paraphrases are leads, not evidence. Retain downloaded originals, URL, exact source text and hashes in `companies-mcp/research-runs/{run_folder}/`. Keep each source's period, units, audit status and known conflicts. A source or tool failure becomes a named data gap. Do not collect documents just to satisfy a quota; stop when the report's material assertions can be supported or their gaps named. Never re-read all originals for every synthesis stage.
2. **Draft the requested report first.** In `drafts/report.md`, cover company identity/history, products and paying-customer economics, management and capital allocation insofar as evidence allows, historical financial position, competition and material risks, and a conditional outlook with observable checkpoints. In `drafts/summary.md`, cover the same view in under 1,000 words. Every material factual line cites its actual `[output_key]`; separate tool-computed figures from filing facts. A current 10-Q is not audited; recognized revenue does not prove every claimed partner is a paying customer. Include material filed acquisitions, commitments, litigation and impairments if they affect the view. State what is unknown. Price or valuation is optional in the report, not a fabricated substitute for missing evidence. Run `dcf_valuation` only when audited historical anchors and its opening working-capital assumption can be reconciled; an unusable model output is excluded with a visible gap. Do not repair a disputed provider input by guessing.
3. **Freeze and scan the drafts.** Retain only sources cited by the drafts in `sources.json` (`issuer_identifier`, `as_of_date`, unique `output_key`, URL, relative `text_file`, `method`, period, and `origin_path` for extracted originals). Retain the complete binaries and deterministic text for cited PDFs; never replace them with summaries. Put the exact report and summary in `drafts/*.md` and 1–25 load-bearing `{id,claim,role,output_key,quote}` records in `key-claims.json`. Include optional `disclosure_inventory` or historical-findings files only if actually checked and well formed. Retain cited computed tool outputs under their `output_key.txt` as `derived`, never audited facts. Call `company_research_packet_build(run_folder)` once. Correct Tier 1 mismatches against the source and rebuild at most once; otherwise name the unresolved gap. Never hand-craft `packet.json` or call a failed builder a pass; builder failure does not prevent provisional incomplete delivery.
4. **Publish before waiting for verification.** Export the exact frozen full and under-1,000-word summary markdown to `~/Documents/zk-data/companies-mcp/reports/{ticker-or-slug}-{date}.md` and `{ticker-or-slug}-summary-{date}.md`. Publish both initially as **INCOMPLETE — not verified, not investment grade** with concrete gaps. After the independent check, change the label to source-verified only if it actually completed without a material finding; otherwise leave both delivered and incomplete. Never alter factual text after checking without rechecking. Keep only cited evidence in the run folder. Report paths, verdict, claim count, unmatched and not-checkable Tier 1 counts, and elapsed time.
5. **Check the already published provisional report once.** Delegate a bounded `verify-late-gate` to an agent that did not write the drafts. Give it only the run folder and `packet_sha256`, not the PDFs or a rendered verification prompt. It must rerun `company_verification_packet_check(run_folder, expected_sha256=packet_sha256)`; rehash the cited retained originals; check every key claim and promoted Tier 1 mismatch against the cited original for period, unit, audited status and context; and inspect material impairments, commitments and risks in the cited filing against both drafts. Record checked claims, omissions, conflicts and unperformed checks in one result. A source identity not independently established is `source_review_status: not_checked`, never verified. A matched figure in a provider output is not an audited figure. A false load-bearing claim gets one correction and a new frozen check; any unresolved or unperformed check yields an incomplete label. Do not invoke `company-research/verification-handoff` or the complete `grounding-verify` workflow for this default report: their forecast, narrative-leak and numerical-scoring protocols do not test whether the two requested reports are delivered. Flash and the optional investment-grade extension retain their own gates.

**Time discipline.** Aim to reach both drafts before spending time on frameworks, optional analyses or exhaustive source hunting. Record elapsed time at collection, draft, check and publication boundaries. If research has not reached drafts within ten minutes, use the evidence already retained, identify missing sections explicitly and draft them as incomplete; if verification cannot finish promptly, deliver an incomplete pair rather than starting another loop. Time is a limit on work, never permission to assert a missing fact or bypass the independent gate for a verified label.

## Investment-grade extension

Only after the requested report is delivered, and only when the user actually requests an investment thesis or investment-grade outcome, use the applicable `company-research/thesis-three-pillars` and `company-research/thesis-judge` gates. This extension must show audited historical anchors, a reconciled valuation, an explicit price conclusion against a ten-year scenario, a durable three-pillar thesis and independent factual verification of any added claim. Dated forecasts, management guidance and add/trim prices belong in Outlook, not the thesis; check these mechanically before judgment. A failure is `needs_work` or `incomplete`, not an upgrade to investment grade; it never delays or retracts the already labelled background/overview/outlook report. Further strategy templates are optional aids, not mandatory stages or evidence.

## Constraints

- `company-research/verification-handoff` remains for the flash and optional investment-grade process; the deep default uses only its frozen packet and a narrow independent check. A packet hash alone never proves source identity or disclosure coverage.
- Full original documents and tool responses stay retained and checkable; model stage prose is synthesis. When provider figures conflict with audited statements, use the audited figures and disclose the conflict.
- A private unpublished original does not go into the public plaintext research run; if it cannot be reviewed on an authorized path, mark the affected evidence `not_checked`.
- Failure or cancellation at any stage surfaces as an incomplete published report with named gaps if at least sourced company identity and material evidence are available. If even identity cannot be resolved, ask only the disambiguating functional question; never invent a company.
