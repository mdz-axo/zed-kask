## Coherence verdict

**`significant_incoherence`** — 6 high-severity findings at L2, propagating through L3/L4/L5. The crate graph is not near-decomposable at the MCP-server tier: 3 servers depend on other servers, and 1 server is a god-server.

The root cause is singular and structural: **MCP servers are acting as domain crates.** The fix is to extract domain crates (`hkask-portfolio`, `hkask-swarm`, `hkask-prediction-markets`) and make the MCP servers thin adapters. This resolves 4 of the 6 high-severity findings.

## Cross-validation with constraints-review

The `constraints-review` drift baseline (same date) found that **L2 is below floor** — no `.rules` constraint addresses crate-graph health. This coherence review confirms the consequence: the 3 surface-to-surface deps and the god-server violate no rule because no L2 rule exists. The two reviews converge on the same highest-leverage action: **add an L2 constraint and extract the domain crates.**

## Caveats

- This is a **manual** run. The Lisp gates (including the cross-level `member` checks) were verified by hand. A runtime execution would verify them mechanically.
- L3 public-item counts were not mechanically counted (inferred from dependency structure). A runtime run with `refactor-architecture` `ra-explore` would produce exact counts.
- L5 did not find code-level bugs — the findings are structural. A runtime run with `code-review` on specific files might surface bugs in the domain logic that's in the wrong layer.
- The L1 comment→seam mapping (38 comments) was not completed. This is a gap in this run, not a clean pass.
