# hkask-keystore

OS keychain integration and AES-256-GCM encryption for hKask.

## Features

- **OS keychain** — stores secrets in the OS-native keystore (Linux: DBus Secret Service)
- **AES-256-GCM** — authenticated encryption for passphrase-protected secrets
- **Auto-provisioned passphrase** — generates a random English word on first run (stored in keychain; user can change it)

## Configuration

| Variable | Description |
|----------|-------------|
| `HKASK_DB_PASSPHRASE` | Database encryption passphrase (env var) |
| `HKASK_MASTER_KEY` | 32-byte master key as 64-char hex (env var) |

### Keychain keys

| Key | Description |
|-----|-------------|
| `hkask-db-passphrase` | Database encryption passphrase (OS keychain) |
| `HKASK_MASTER_KEY` | Master key hex (OS keychain) |
| `a2a-secret` | A2A root-authority secret |
| `ocap-secret` | OCAP signing secret (fails closed if master key is unavailable) |
| `signing-keys/{publisher}` | Publisher's Ed25519 signing key for kask skill marketplace manifests |

## Skill marketplace signing

The `signing` module provides Ed25519 keypair generation, signing, and
verification for kask skill manifests ("Kask Skill Signing & Trust Model"
plan). Keys are generated by the publisher and stored in the OS keychain
under `signing-keys/{publisher}`; the manifest carries the public key, the
signature over its canonical bytes, and an `expires_at` set at signing time.
The collab server verifies the signature and enforces the window
(`now < expires_at <= now + KEY_MAX_AGE_DAYS`) at upload and on its periodic
poll; expired skills are filtered from the catalog and purged.
