## Storage and credentials

- **DB:** `{kask_data_dir}/mcp/kata-kanban/kanban.db` (D28 layout; override
  via `HKASK_KANBAN_DB`, a non-secret config path read via `config_env`).
  SQLCipher via `hkask_storage::open_or_repair` — the server **requires**
  `HKASK_DB_PASSPHRASE` and refuses startup without it (the
  `kanban_startup_requires_durable_storage` pin: missing durability is an
  explicit startup failure, never a volatile fallback). Replay protection
  (`idempotency.rs`) shares the same database, so protection has the same
  durability as the writes it guards.
- **Credential declaration:** `CredentialRequirement::required("HKASK_DB_PASSPHRASE")`
  — the `.rules` reference pattern for DB-backed servers.

## Surfaces

- **Boards:** create (idempotent), list, delete (owner-gated,
  `permission_denied`), rename (owner-gated), mermaid export/import
  (round-trip pair; import is replay-safe and atomic).
- **Goals:** MCP create/judge/get/list only. Create requires real specification
  `source: { interaction_id, session_id, source }`, immutable criteria, optional
  `supersedes`, and an optional typed `forecast`, not routine `prediction`.
  Create/get/list return full aggregates with `id`, `criterion_ids`, `spec_digest`.
  Judge appends worker progress, never human acceptance. Native host
  `kanban_goal_close` takes `goal_id` and evidence only and obtains the six-way
  accomplished/stop × achieved/not-achieved/unknown decision via human
  `ActionChoice`. Native `kanban_goal_correct_outcome` is a separate authenticated
  append-only correction. These are not MCP routes. Canonical history persists
  after receipt-validated projection; no prune-on-ack. See `kask/mcp-servers/hkask-mcp-kata-kanban/GOAL_INTERFACE.md` for exact types.
- **Tasks:** create (idempotent; goal-criterion citations validated at
  creation), update (owner-gated), list, move (status transitions; the
  Algedonic review board requires `kanban_task_verify` in Review to reach
  Done), assign/unassign, delete, verify (evidence text is the pass
  signal), comment/comments-since (the subagent↔agent feedback thread and
  the incremental memory-ingestion channel), add-deliverable, reopen,
  kata-prompt, spawn (worktree-isolated via the parent-authorized
  `WorktreeSpawnPort`; a missing grant or uncertain reply never starts a
  fallback), delegate-result (the structured verdict readback).
- **Idempotency:** `with_idempotency` — three-outcome replay semantics
  (fresh / replay-verbatim / refused-pending), fail-closed reservation,
  the post-effect rule (bookkeeping failures fold into the response;
  releasing the claim would let a retry duplicate the effect), and the
  spawn special case (an `Unavailable` spawn may have landed; the pending
  claim stays).

## Assessment, forecasts and delivery

The host bridge `kask/crates/kask_bridge/src/goals.rs` leases a fresh blinded
assessment of frozen spec/criteria, untrusted manifest and host-read artifact
snapshots, excluding worker verdicts, human choice, probabilities and scores.
`goals/artifacts.rs` reads only native-approved absolute local paths/local file
URIs: canonical, nofollow UTF-8 regular files; at most 16 artifacts, 64 KiB content
each and 256 KiB aggregate read budget per attempt, including growth probes.
There is no network retrieval, directory crawling, symlink traversal or execution.
The native prompt discloses exact paths/hashes, sharing with the configured
assessor including retries, attempt/recall retention and retained projection
sharing with the configured semantic-indexing provider. Historical absent consent
is not retroactive permission; corrections expand neither access approval.

Fetched contents and unavailable/mismatch receipts are retained with the exact
attempt input/digest before inference. Without fetched contents the host records
unknown findings deterministically and makes no model call. Otherwise supported/
contradicted findings need actual fetched, digest-matched evidence IDs; manifest
references alone cannot support them. Files remain untrusted data. Reading an
alleged test log proves bytes, not authentic production or that a command ran.
Failures remain visible/retryable; assessment never supplies a human label.

Optional `GoalForecast` freezes proposition, probability, horizon, resolution
window, policy/resources, baseline, cohort and `fixed_at_declaration` policy.
Supported resolvers are `HumanAcceptance` and exactly
`MachineArtifactDigest { locator, expected_sha256 }` (wire tag
`machine_artifact_digest`); arbitrary old `MachineEvidence` is unsupported history.
The native closure separately discloses the digest resolver path/hash/window,
independently of the assessment manifest, and binds `machine_artifact_access`
consent to the full frozen forecast/spec. Manifest consent is not this approval.
At the first actual bounded source read in inclusive `[horizon, resolution_deadline]`,
core derives true for SHA-256 equality and false for a successful different hash.
Missing/denied/unsafe/oversized/non-UTF-8/late reads are unknown and unscored,
not false; the first receipt is immutable, including unknown. It never reuses
pre-horizon assessment contents, human labels or assessor findings. Only the
source receipt is retained/indexed; resolver-only contents are discarded, not
shared with assessor/indexer. Digest equality is not evidence that tests ran.
Scoring still awaits an assessment attempt independently of source-read timing.
Versions do not add independent cases; closure requires no forecast or score.

Native tools require an explicit offered `ActionChoice` ID; generic permission
and granularity shortcuts accept only `PermissionGrant`, never a human outcome.
The write profile exposes native close/correction, but their decisions cannot be
auto-granted through configurable permission settings. Exact pact:
`kask/mcp-servers/hkask-mcp-kata-kanban/GOAL_INTERFACE.md`.
Canonical storage holds assessment leases and complete snapshot projections with
stable event ID, revision and payload digest. The scheduled host drainer retries
after startup without a model turn, validates delivery receipts, and never deletes
the aggregate or changes memory confidence from loss. Legacy raw JSON is archived
as provenance-limited, not promoted into prospective forecasts.
