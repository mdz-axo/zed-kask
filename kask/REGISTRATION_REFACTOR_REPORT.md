## Follow-up: skill-seeding trigger decision (2026-09-22, committed as `e1391f9ccc`)

The two seeding **call sites** remain 2 → 2, but the seeding **implementation** was already 1 → 1 (`crates/agent_skills/agent_skills.rs:795-831`). This candidate does not offer safe codegraph compression under the zero-drift requirement. `crates/zed/src/main.rs:741-766` starts a detached seed/load/publish task so Settings can show globals before any panel interaction (introduced in `349bc7718b`). `crates/agent/src/agent.rs:752-797` seeds on first panel scan before watching and refreshing project contexts, so an interaction racing the detached startup task still loads shipped skills; fake filesystem tests intentionally skip this seeding (`:765-772`). The actual project-context disk load is at `crates/agent/src/agent.rs:1273-1284`. Core skills are rewritten by the common seeder and non-core edits are preserved (`crates/agent_skills/agent_skills.rs:808-830`, tests `:2413-2450,2480-2517`).

**Review adjudication:** IS: the triggers have different owners and timing, not duplicated registration logic. OUGHT: keep both; deleting startup would make Settings depend on opening the panel, while deleting the scan trigger would make first interaction depend on asynchronous startup completion. Falsifier for a future single-trigger design: exercise *both* interleavings of startup seed completion and first panel scan, and check the Settings `SkillIndex` plus the agent's project skill catalog, without weakening fake-FS tests. `NativeAgent::new` preserves an existing index (`crates/agent/src/agent.rs:685-687`), but startup's unconditional `cx.set_global` (`crates/zed/src/main.rs:760-765`) could overwrite an index published by the agent (`crates/agent/src/agent.rs:1681-1721`) if it finishes later; this is a separately identified race, **not** a behavior-preserving registration refactor, and is not patched here. Neither a timer nor a process-global once-cell tied to a particular filesystem is a safe substitute for ordering evidence. Any future upstream edit must update D1/D28 in `DIVERGENCE.md` and add a behavioral pin in the same pass. No source code, settings, or test was changed in this follow-up; this decision edits only this report. Verification: `cargo test -p agent_skills test_seed_shipped_skills --lib` (2 passed), `cargo test -p agent test_global_skills_load_and_reload --lib` (1 passed), and `git diff --check` (passed).
